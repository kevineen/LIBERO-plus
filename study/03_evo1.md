## 要点

### アーキテクチャ（実装に効く粒度）

```text
InternVL3-1B（VLM） + action expert（flow matching 等）
観測: 複数カメラ画像（必要なら dummy）+ state + prompt
出力: action chunk（次元は pad して統一しやすい）
```

多エンボディメント向けに **action / state を 24D にパディング**し、`action_mask` / `image_mask` で有効次元・有効カメラを示す。

### 二段階 Fine-Tuning

| Stage | 何を学習するか | 意図 |
|-------|----------------|------|
| 1 | integration + action expert（VLM は実質凍結寄り） | 行動ヘッドを載せつつ **意味空間を壊しにくい** |
| 2 | VLM + action（フル） | タスク適合。やりすぎると言語意味が崩れるリスクとのトレードオフ |

PARC では SmolVLA 向けに二段階 FT YAML 草案がある（実行は別承認）。仮説: Language OOD / semantic 保持。

### 推論 I/F（WebSocket）

```text
Terminal 1:  conda/Evo1  →  python scripts/Evo1_server.py   # 重みパスを編集
Terminal 2:  sim env     →  client（libero / metaworld / libero-plus-eval）
```

Client が送る obs の典型キー（xArm 例・README より）:

- `image`: リサイズ済み（例 448×448）のリスト
- `image_mask`: どのカメラが有効か
- `state` / `action_mask` / `prompt`

### LIBERO-plus（著者公表・自前再測ではない）

[`baselines/evo1/libero_plus.md`](../parc/docs/baselines/evo1/libero_plus.md) より要約:

| | Camera | Robot | Language | Avg |
|--|-------:|------:|---------:|----:|
| 全体目安 | ~44.9% | ~49.4% | ~63.6% | **~65.7%** |

PARC の Camera / Robot 弱点と重なる **外部天井**として読む。parc-eval 同尺の自前薄スライスが正。
