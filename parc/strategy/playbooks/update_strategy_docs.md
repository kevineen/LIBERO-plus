# Playbook: strategy ドキュメント更新

方針メモ（`strategy/01`–`05`）はエージェントがメンテする。  
オペ手順（`docs/`）はセットアップ変更時以外いじらない。

## いつ更新するか

| トリガー | 更新ファイル |
|----------|----------------|
| キュー状態が変わった（投入・完了・失敗） | `01`（必須）、`03` |
| 新しい metrics が確定 | `02`（必須）、必要なら `05` の「現状」行 |
| バックログの完了 / 追加 | `03` |
| Fleet/SSH/役割の変更 | `04` |
| Gate や禁止事項の変更 | `05` |
| スナップショット日付 | `README.md` の「最終更新」と `01` 冒頭 |

## 01_current_status.md

- 冒頭の時点を **今日の日付**に
- マシン表の running / queued / 直近完了を実測に合わせる
- 推測で埋めない。不明は「未確認」

## 02_results_and_findings.md

- 表に行を足す（上書きで履歴を消さない。厚い/薄いは列で区別）
- run_id を残す（短縮可だが一意に辿れること）
- 「解釈」は 2–4 行。長い考察はユーザー向けチャットに書く

## 03_next_actions.md

- 完了は `[x]`
- 進行中は `[ ]` のまま「進行中」節へ
- 新しい Backlog は優先順を守って挿入
- やらないことは取消線のまま残してよい（再発防止）

## 書式

- 日本語で簡潔に
- 絶対パスは machines が違うので、表では run_id 優先、path は必要なときだけ
- 秘密（Webhook URL、鍵）は書かない

## 更新後の自己チェック

- [ ] `01` の時点と実キューが一致
- [ ] `03` の「進行中」が実 running と一致
- [ ] 矛盾する「次の一手」が `03` と `05` に同時に書いていない
